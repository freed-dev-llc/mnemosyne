# RAG 101 — Retrieval-Augmented Generation, from first principles

> This is the teaching core of Mnemosyne. Read it once before touching the code; every
> module in `src/mnemosyne/` is one box in the diagram below. The goal is that nothing
> here feels like magic.

## The problem RAG solves

A language model is frozen at training time. It is excellent at *general* language and
reasoning, and ignorant of anything it did not see — your internal docs, last week's
firmware release notes, the specific Ubiquiti adoption quirk you hit this morning. There
are three ways to fix that ignorance:

1. **Retrain / fine-tune** — bake the knowledge into the weights. Slow, costly, and stale
   the instant the docs change. Great for *behavior*, poor for *facts*.
2. **Stuff everything into the prompt** — paste the whole manual every time. Blows the
   context window, costs tokens, and buries the model in irrelevant text.
3. **Retrieve just what matters, then generate** — at question time, find the handful of
   passages relevant to *this* question and put only those in the prompt.

Option 3 is **Retrieval-Augmented Generation**. The model's weights never change. We change
what we *show* it. The slogan: **don't teach the model the manual — hand it the right page.**

## The whole pipeline in one breath

```
INGEST (offline, once per corpus)            ASK (online, every question)
─────────────────────────────────           ──────────────────────────────
documents                                    question
   │ load                                        │ embed (same model!)
   ▼                                             ▼
raw text                                     query vector
   │ chunk                                       │ search
   ▼                                             ▼
passages                                     FAISS: k nearest chunks
   │ embed (Ollama)                              │ stuff into prompt
   ▼                                             ▼
vectors ──► FAISS index ──(disk)──────────►  LLM (Ollama) ──► grounded answer + citations
```

Two phases. **Ingest** is the slow, do-it-once part: turn a pile of documents into a
searchable index of meaning. **Ask** is the fast, do-it-often part: turn a question into
the same kind of vector, find the nearest passages, and let the model answer using them.

## Stage by stage

### 1. Load — get clean text out of messy files
**Module:** [`loaders.py`](../src/mnemosyne/loaders.py)

Documents arrive as Markdown, PDF, HTML, plain text. The loader's only job is to produce
plain text plus **metadata** (source path, title, page/section). That metadata is what
later becomes a *citation* — so capture it now or you can never cite it.

### 2. Chunk — cut text into retrievable units
**Module:** [`chunking.py`](../src/mnemosyne/chunking.py)

You cannot retrieve "a document" usefully — it's too big to embed meaningfully and too big
to fit in a prompt. You retrieve **chunks**: a few hundred tokens each. Chunking is the
single highest-leverage knob in RAG. Two ideas matter:

- **Size.** Too small and a chunk loses context ("set this to 9000" — set *what*?). Too big
  and the embedding becomes a blurry average of many topics and retrieval gets noisy.
  A few hundred tokens is the usual sweet spot.
- **Overlap.** Let consecutive chunks share a little text so a sentence split across a
  boundary still lands whole in at least one chunk.

We use LangChain's `RecursiveCharacterTextSplitter`, which tries to break on natural
boundaries (paragraphs, then sentences) before resorting to a hard cut.

### 3. Embed — turn text into vectors of meaning
**Module:** [`embeddings.py`](../src/mnemosyne/embeddings.py)

An **embedding model** maps a chunk of text to a fixed-length vector (e.g. 768 numbers)
such that *texts with similar meaning land near each other* in that space. "Adopt a
switch" and "add a device to the controller" end up close even though they share no words.

We use Ollama's `bge-m3` — local, multilingual, and strong for retrieval (the rag_ollama
default). **The iron rule:** embed your chunks and your queries with the *same* model.
Mixing embedders makes distances meaningless.

### 4. Index — make nearest-neighbor search fast
**Module:** [`index.py`](../src/mnemosyne/index.py)

With thousands of vectors, you need to find the nearest few to a query *fast*. That is what
[FAISS](https://github.com/facebookresearch/faiss) does — an in-memory index optimized for
similarity search, with a one-line save/load to disk. The saved index *is* the memory: a
file you build once and reuse (and could even ship alongside a pack).

A note on similarity: we compare vectors by cosine similarity (angle), not raw distance, so
length doesn't bias the match.

### 5. Retrieve — fetch the k most relevant chunks
**Module:** [`pipeline.py`](../src/mnemosyne/pipeline.py)

At question time: embed the question with the same model, ask FAISS for the **top-k**
nearest chunks, and carry their text *and metadata* forward. `k` is a tradeoff — too few
and you miss the answer; too many and you dilute the prompt and pay for tokens. Start at
4–6 and tune with evals.

A refinement worth knowing: a **relevance floor**. "Nearest" is not the same as "relevant":
for an off-topic question FAISS still returns its k nearest chunks, they are just all far
away. Dropping any chunk past a distance threshold means a question with nothing close enough
retrieves *nothing*, and the model can answer "not in the knowledge base" instead of writing a
confident answer over irrelevant context.

### 6. Generate — answer grounded in what was retrieved
**Modules:** [`prompts.py`](../src/mnemosyne/prompts.py), [`llm.py`](../src/mnemosyne/llm.py)

Finally, build a prompt that says, in effect: *"You are an expert on X. Using ONLY the
context below, answer the question. Cite your sources. If the context doesn't contain the
answer, say so."* Then send it to a local Ollama chat model. Two properties make this
trustworthy:

- **Grounding.** Telling the model to use only the retrieved context — and to admit when
  it's missing — is what keeps RAG honest and suppresses hallucination.
- **Citations.** Because every chunk carries its source metadata, the answer can point back
  at exactly which document and section it came from. An answer you can check is an answer
  you can trust.

## How to know it's working (and the failure modes)

RAG fails in two distinct places, and conflating them wastes hours:

- **Retrieval failure** — the right chunk never made it into the top-k. The model answered
  from thin air because it was *given* nothing useful. Fixes live upstream: chunking, the
  embedding model, `k`, query phrasing. *Check this first* — print the retrieved chunks.
- **Generation failure** — the right chunk *was* retrieved, but the model ignored it,
  misread it, or padded with invented detail. Fixes live in the prompt and model choice.

The discipline that separates the two: **always be able to see what was retrieved.** That's
why `mnemosyne ask --show-sources` exists. v0.2's eval harness turns these into numbers —
retrieval hit-rate and answer faithfulness — so a chunking change is *provably* better, not
just vibes.

## Mental model to keep

- RAG changes **what the model sees**, never **what the model is**.
- **Ingest is for meaning; ask is for relevance.** Spend your tuning budget on chunking and
  retrieval before you touch the prompt.
- A RAG answer is only as good as its worst stage — and the cheapest stage to get wrong is
  chunking.
